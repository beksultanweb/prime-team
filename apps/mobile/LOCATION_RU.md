# Геопозиция Prime Team

В профиле: **Геопозиция → включить/выключить**. Новый вход не включает сбор автоматически. Перед первым включением показываются отдельные условия, затем запрашиваются нативные разрешения телефона.

Ежедневно **07:00–21:00 (Asia/Almaty)**; целевой интервал **5 минут**. Вне окна координаты не сохраняются. Отказ от разрешений не мешает чату и авторизации. Выключение очищает локальную очередь и отзывает геосогласие; logout/смена сайта/новый вход останавливает только данный телефон. При недоступном сервере локальный сбор остановлен, а отзыв серверного согласия можно повторить через профиль.

ОС может задерживать фоновые события. Принудительно закрытое приложение нужно открыть снова. После ночной остановки **автоматическое пробуждение в 07:00 не гарантировано**: сбор возобновляется при следующем открытии/активном исполнении. Точное отключение системной GPS-подписки при полностью приостановленном JS тоже не обещается; ночные координаты отбрасываются на устройстве и сервере.

Фоновый режим требует новой нативной сборки (`expo-location`, `expo-task-manager` и разрешения). JS export не устанавливает бинарник и не доказывает работу на телефоне. iOS background нельзя проверить в Expo Go.

В серверных настройках есть нативная карта с полигоном из предоставленной Яндекс-карты. Сервер назначает **IN** внутри, **OUT** снаружи, **UNKNOWN** у границы в пределах точности GPS либо без полигона. Через 10 минут без новой точки статус становится UNKNOWN. Внешний JS Яндекса в приложение не добавляется.

DEV build: `EXPO_PUBLIC_PRIME_SITE_URL=https://dev.primegc.kz`; без override адрес по умолчанию `https://app.primegc.kz`. Backend должен включить доступность в **Prime Mobile Location Settings**, определить согласованную цель/срок хранения. По умолчанию функция сервером выключена; существующие пользователи/роли не изменяются. Сервер и приложение проверяют согласие и пользователя. Последняя точка находится в **Prime Mobile Location Point**, чтение: собственная, либо системный администратор.

Отдельный серверный флаг GPS-отметок и Company разрешает создание **Employee Checkin** после двух последовательных подтверждающих измерений с интервалом не менее 5 минут, без повторной ЭЦП. Нужны связанная eGov identity, юридическое принятие, геосогласие и однозначный Active Employee. Повторные входы/выходы — отдельные отметки; UNKNOWN/нет связи/21:00 не означают конец рабочего дня. Вчерашний пропущенный выход исправляет HR. Устройство события копируется в кадровую запись; маршрута/координат в Checkin нет. Настройка смен/Auto Attendance остаётся в HRMS; GPS не является ЭЦП или доказательством отработанных часов. GPS-отметки по умолчанию выключены, до физического UAT их не включать.

На телефоне и сервере хранится только последняя геопозиция, без маршрута и истории координат. В SecureStore неотправленная точка действует не более 10 минут и заменяется новой. Старые/ночные точки и очередь при logout/выключении удаляются; это не обещание доставки без потерь. Не принимать GPS как доверенное доказательство присутствия.

С точкой передаются случайный UUID установки приложения (SecureStore), ОС и модель телефона. Это заявленные приложением сведения, не аппаратная аттестация/привязка: не IMEI/MAC/advertising ID. После переустановки/удаления защищённого хранилища ID может измениться; сохранение iOS Keychain при переустановке может оставить прежний ID.

Проверки: `yarn test:location`, `yarn test:auth`; сервер `tests/release/test_prime_team_location.py`. Перед включением пилота/PROD нужны DEV миграция, реальный iOS/Android UAT, фон/границы окна/permissions/offline/auth expiry и проверка доступа к чужим данным. Публикация исходников сама по себе не обновляет сервер и установленное приложение.
